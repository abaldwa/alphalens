# Phase 1 Data Model: ML Strategy Adapter

**Date**: 2026-08-25 | **Status**: Complete

## Entities

### MLStrategyAdapter

**Purpose**: Bridge between pre-trained ML models and the backtest engine; implements `StrategyAdapter` protocol.

**Key Attributes**:
- `model_name` (str): Name of pre-trained model (e.g., "catboost_v1", "ridge_v2")
- `model_version` (str): Semantic version of model (e.g., "1.0.0")
- `lookback_days` (int): Number of historical days used for feature engineering (e.g., 63, 126, 252)
- `feature_set` (list[str]): Names of features fed to model (e.g., ["momentum_12m", "delivery_ratio", "fundamentals"])
- `prediction_threshold` (float): Confidence threshold for long signal (e.g., 0.55); scores >= threshold → long, else flat
- `regime_overlay` (str, optional): Name of regime overlay to apply (e.g., "ema_rsi_v1"); applies after signal generation

**Relationships**:
- Loads from: `baselines/` (pickled/joblib model files)
- Writes to: `strategy_signals` table (daily signals)
- Participates in: `strategy_registry` (versioned strategy definitions)
- Reads from: `strategy_sweep` parameter grids (for sweep orchestration)

**Validation Rules**:
- `model_name` must match a file in `baselines/` directory
- `lookback_days` must be > 0
- `prediction_threshold` must be in range [0.0, 1.0]
- `feature_set` entries must match available feature names in `features/` module

**State Transitions**:
- Initialization: Load model from `baselines/`
- Per backtest run: `generate_signals()` → `generate_portfolio()` → `execute_trades()`
- Per parameter sweep: Repeat above for each parameter grid combination
- Per walk-forward fold: Repeat above for train/test date ranges

### MLSignal

**Purpose**: Daily trading signal generated by ML model; auditable record of model prediction and resulting trade.

**Key Attributes**:
- `strategy_id` (str): Reference to strategy in `strategy_registry`
- `date` (date): Date of signal (YYYY-MM-DD)
- `symbol` (str): Stock ticker (e.g., "SBIN")
- `signal` (str): "long", "flat", or "cash" (discrete position)
- `prediction_score` (float): Raw model output before thresholding (e.g., 0.0–1.0 for CatBoost)
- `feature_vector` (json): Snapshotted features used for prediction (for auditability)
- `model_version` (str): Model version used to generate signal
- `created_at` (datetime): Timestamp of signal generation

**Relationships**:
- Persisted to: `strategy_signals` table (existing schema)
- References: `strategy_registry` (by strategy_id)
- Audits: trades executed on this signal

**Validation Rules**:
- `signal` must be one of: "long", "flat", "cash"
- `prediction_score` must be numeric (allow NaN, Inf with warning)
- `date` must be valid trading date (NSE calendar)
- `feature_vector` must be valid JSON (or null)

**State Transitions**:
- Generated: when `generate_signals()` is called
- Persisted: after validation (logged to `strategy_signals` table)
- Consumed: by `generate_portfolio()` to build positions
- Traded: by `execute_trades()` to generate trades

### StrategyAdapter Interface (Existing)

**Purpose**: Protocol that all strategy adapters must implement.

**Required Methods**:

#### `generate_signals(dates: List[date], universe: List[str]) -> Dict[str, Dict[date, Signal]]`
Generates daily signals for all symbols in universe over date range.

**Parameters**:
- `dates`: List of trading dates
- `universe`: List of stock tickers to generate signals for

**Returns**: Dictionary mapping symbol → (date → signal)

**Implementation (MLStrategyAdapter)**:
1. For each date in `dates`:
   a. Load features for all symbols in `universe` at point-in-time (as of date)
   b. Load pre-trained model from `baselines/`
   c. Run prediction: raw_score = model.predict(features)
   d. Threshold: if raw_score >= threshold → signal = "long", else signal = "flat"
   e. Persist to `strategy_signals` table
2. Return signal dictionary

**Error Handling**:
- If model is missing: raise FileNotFoundError with clear message
- If feature engineering fails (returns NaN): log warning, skip symbol for that date
- If model prediction fails (returns Inf): log warning, skip symbol for that date

---

#### `generate_portfolio(signals: Dict[str, Signal], weights: Dict[str, float]) -> Portfolio`
Converts signals to portfolio positions, applying universe filtering and regime overlay.

**Parameters**:
- `signals`: Dictionary mapping symbol → signal for today
- `weights`: Weight allocation for "long" positions (uniform by default)

**Returns**: Portfolio object with positions and cash allocation

**Implementation (MLStrategyAdapter)**:
1. Filter signals by universe (discard signals for symbols not in universe)
2. Apply regime overlay if configured (e.g., EMA-RSI exposure gating reduces position count)
3. Allocate weights: long signals get equal weight, flat positions are zeroed
4. Compute portfolio weights as fraction of total capital
5. Return Portfolio object

**Error Handling**:
- If all signals are "flat": return all-cash portfolio (valid state)
- If regime overlay fails: log warning, proceed without overlay

---

#### `execute_trades(portfolio: Portfolio, prices: Dict[str, float]) -> List[Trade]`
Executes rebalance trades to move from current positions to target portfolio.

**Parameters**:
- `portfolio`: Target portfolio (from `generate_portfolio()`)
- `prices`: Current market prices for all symbols

**Returns**: List of executed trades with prices, quantities, P&L

**Implementation (MLStrategyAdapter)**:
1. Compute position deltas: target_quantity - current_quantity
2. For each symbol with non-zero delta:
   a. Compute order quantity
   b. Execute trade at current price
   c. Log trade to trade ledger
3. Compute P&L from trade execution
4. Return trade list

**Error Handling**:
- If price is missing for a symbol: raise ValueError with clear message
- If order size exceeds liquidity: log warning, scale order down (out of scope for v1)

### Registry Entry Schema (Existing)

**Table**: `strategy_registry`

**ML-Specific Columns**:
- `strategy_id`: Unique identifier (e.g., "ML-CATBOOST-V1")
- `domain`: "ml"
- `name`: Human-readable name (e.g., "CatBoost Daily Momentum Classifier")
- `model_name`: Model identifier (e.g., "catboost_v1")
- `model_version`: Model version (e.g., "1.0.0")
- `lookback_days`: Feature lookback period (e.g., 63)
- `parameters`: JSON with threshold and other hyperparameters
- `active`: Boolean flag (true if strategy can be used in backtests)
- `created_at`: Registration date
- `updated_at`: Last modification date

**Validation**:
- `strategy_id` must be unique
- `model_name` must match file in `baselines/`
- `lookback_days` must be > 0
- `parameters` must include `prediction_threshold` key

## Data Flow Diagram

```
┌─────────────────────────────────────────────────────────────┐
│ Strategy Registry (versioned strategy + model metadata)     │
└─────────────────────────────────────────────────────────────┘
                          ↓
        [MLStrategyAdapter.generate_signals()]
                          ↓
        Load Features (features/) + Model (baselines/)
        Predict → Threshold → Signal (long/flat/cash)
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ Strategy Signals Table (persisted for auditing)             │
│ (strategy_id, date, symbol, signal, prediction_score, ...) │
└─────────────────────────────────────────────────────────────┘
                          ↓
        [MLStrategyAdapter.generate_portfolio()]
                          ↓
        Apply Universe Filtering + Regime Overlay
                          ↓
        Target Portfolio (positions + cash)
                          ↓
        [MLStrategyAdapter.execute_trades()]
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ Trade Ledger (executed trades + P&L)                        │
│ Backtest Metrics (Sharpe, CAGR, Drawdown, ...)             │
└─────────────────────────────────────────────────────────────┘
```

## No Schema Changes Required

The ML adapter reuses existing tables and schemas:
- `strategy_registry`: Add new rows with domain='ml' (no schema change)
- `strategy_signals`: Existing table accepts ML signals (no schema change)
- `strategy_sweep`: Existing table accepts ML strategy parameter grids (no schema change)
- Trade ledger, backtest metrics: Existing tables, adapter-agnostic

This reflects the YAGNI principle (Principle I): no unnecessary database changes, pure adapter implementation.
