# Archive Directory

Legacy documentation and completed phase files are stored here for historical reference.

## Purpose

This directory contains:
- **Completed phase files** — Historical implementation plans (PHASE_*.md, etc.)
- **Superseded plans** — Earlier iterations of design decisions now integrated into specs/
- **Session logs** — Build summaries and decision records from past sessions
- **Deprecated guides** — Setup guides for features no longer active

## Why Keep It?

Archived files preserve:
1. **Decision rationale** — Why choices were made (useful for future refactoring)
2. **Known issues** — Bugs/gaps documented in past phases
3. **Partial solutions** — Code patterns or approaches to revisit
4. **Timeline context** — When features were built and what was priority

## Usage

- **Read-only** — never edit archived files
- **Reference only** — link to archive when citing past decisions
- **Link to specs/** — if archival suggests a new spec is needed, create it in `specs/`
- **Quarterly review** — every 90 days, assess whether any archive items should be deleted (never modified)

## Adding to Archive

When moving a file here:

1. Timestamp the filename: `original_name_YYYYMMDD.md`
2. Add a one-line summary to the Contents table above
3. Never edit the file again (preserve historical accuracy)

---

**Note**: This directory exists to support decisions, not to clutter the active project. If you find yourself constantly reading archive files, consider moving that content into an active spec or plan.
