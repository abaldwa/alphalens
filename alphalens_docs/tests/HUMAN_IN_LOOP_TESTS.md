# AlphaLens — Human-in-the-Loop Test Cases
## Complex · Maximum Business Value · Requires Human Judgment

These test cases CANNOT be automated. They require a human investor to evaluate
system outputs against real-world knowledge, market context, and domain judgment.
Each case is designed to catch failures that automated tests miss: plausible-sounding
but wrong predictions, missing context, misleading explanations, or dangerous edge cases.

**Run these:** Before each major model retrain, before going live with any new model version,
and quarterly as part of the model transparency review.

---

## HITL-01: The Upcoming Fraud Test
**Business Value: CRITICAL — prevents catastrophic loss**
**Complexity: HIGH — requires cross-referencing multiple signals**

**Setup:** Select 3 stocks from the historical Indian fraud list (Vakrangee, Manpasand,
Satyam) at a date 6–12 months BEFORE their fraud became public knowledge.

**Test procedure:**
1. Feed features as of that historical date into the forensic model
2. View the forensic dashboard for each stock
3. Human evaluates: Does the system flag this stock as a fraud risk?

**Pass criteria:**
- [ ] Forensic composite score > 60 (Red flag) for at least 2 of 3 stocks
- [ ] At least 3 specific forensic drivers visible in SHAP explanation (not generic "high accruals")
- [ ] Alert text is specific enough to motivate investigation (not just "anomaly detected")
- [ ] System does NOT flag a comparable clean company in the same sector as Red

**Failure modes to check:**
- System produces Red flag but explanation is so vague it could apply to any company
- System correctly flags accruals but misses the promoter pledge spiral
- System gives Red flag for the wrong reasons (leading to false positives)

**Expected output example:**
```
SCAM_CO forensic score: 74 (RED)
Top drivers:
1. cfo_to_net_income: 0.21 (should be > 0.8) — profits NOT backed by cash
2. benford_revenue_chi2: 18.4 (critical deviation) — revenue digits unnatural
3. promoter_pledge_pct: 68% and rising — pledge spiral risk
4. related_party_transaction_intensity: 31% — excessive RPT
Pattern match: Similar to Manpasand Beverages pre-2019
```

## HITL-02: The Market Crash Regime Test
**Business Value: HIGH — prevents drawdowns in bear markets**
**Complexity: HIGH — requires understanding regime transitions**

**Setup:** Use data from March 2020 (COVID crash). Set features as of February 28, 2020
(Nifty 50 had already dropped ~10% but majority of crash was ahead).

**Test procedure:**
1. View the HMM regime dashboard for Nifty 50 and 10 individual stocks
2. Check position sizing recommendations for that date
3. View what the signal models recommend
4. Compare with what ACTUALLY happened in the next 21 days (Nifty fell further ~30%)

**Pass criteria:**
- [ ] Market-wide HMM shows regime = Bearish OR Volatile (not Bullish)
- [ ] Position sizing is visibly reduced vs the prior bull-market period
- [ ] Signal models show predominantly Hold/Sell (not overwhelmingly Buy)
- [ ] At least some stocks show regime transition flag active
- [ ] Dashboard communicates the regime context clearly to the human user

**Failure modes to check:**
- HMM still shows Bullish regime on 2020-02-28 (lagging indicator problem)
- System gives confident Buy signals just before a 30% crash
- Regime change is detected but position sizing rules don't respond
- Dashboard doesn't surface regime context prominently enough

**Human judgment required:** The HMM may legitimately lag by a few days. The human
must judge whether the 2–5 day lag is acceptable given the severity of the subsequent crash.

## HITL-03: The Multibagger Retrospective Test
**Business Value: HIGH — validates the core value proposition**
**Complexity: HIGH — requires long-term market knowledge**

**Setup:** Take the top 20 multibagger watchlist as generated by the model using data
from January 2021. Compare against actual 3-year returns through January 2024.

**Test procedure:**
1. View the weekly multibagger watchlist as of Jan 2021
2. For each stock in top-20, note: probability score, tier prediction, archetype
3. Look up actual 3-year return for each stock
4. Evaluate quality of predictions

**Pass criteria:**
- [ ] At least 5 of top-20 (25%) achieved 2x or more within 3 years
- [ ] At least 2 of top-20 achieved 3x or more
- [ ] Stocks in the bottom-20 (lowest ranked) underperformed top-20 on average
- [ ] Archetype labels are plausible (human confirms "Long Base Breakout" genuinely had a long base)
- [ ] SHAP explanations identify features that human investors would also consider important

**IMPORTANT — apply the honest caveat:**
Given our truthful expectations document, 25% of top-20 achieving 2x is a realistic
minimum bar. The human reviewer should explicitly ask: "Is this better than what I'd
get from a simple momentum screen?" That is the real benchmark.

**Failure modes to check:**
- Top-20 is filled with P&D stocks that pumped briefly and then crashed
- High-probability stocks are all in the same sector (concentration risk)
- The SHAP explanations don't match why a human investor would have liked these stocks
- System predicts 2x for a stock that went bankrupt

## HITL-04: The Exit Signal Legibility Test
**Business Value: HIGH — the quality of exit communication determines real losses prevented**
**Complexity: MEDIUM**

**Setup:** Take 5 historical exit signals generated by the model. Include:
- One correct exit (stock fell significantly after signal)
- One false alarm (stock recovered after signal)
- One P&D exit (stock was being manipulated)
- One thesis-broken exit (promoter pledge spiked)
- One momentum exhaustion exit (technical signal)

**Test procedure:**
1. Present each exit alert as the user would see it on the dashboard
2. Human investor reads the alert WITHOUT knowing which outcome occurred
3. Human decides: "Would I act on this? Is the explanation clear enough?"

**Pass criteria:**
- [ ] For each alert, human can identify: WHY (specific reason), HOW URGENT (0–100 score), WHAT TO DO (exit all / reduce 50% / monitor)
- [ ] Exit TYPE is visible and specific ("Promoter pledge 8% → 22%" not just "governance concern")
- [ ] SHAP explanation matches the exit type label
- [ ] Human agrees the P&D exit alert is more urgent than a technical exit alert
- [ ] Alert for the false alarm does NOT appear worse than alert for the correct prediction
  (system should have uncertainty — both cases had real risk signals)

**Failure modes to check:**
- All exit alerts look identical despite different exit types
- Urgency scores don't correspond to severity of the underlying signal
- P&D exit alert buries the lede (manipulation risk not prominently shown)
- SHAP explanation shows irrelevant features as top drivers

## HITL-05: The Sector Rotation Test
**Business Value: MEDIUM-HIGH — prevents being long a sector while rotation is occurring**
**Complexity: HIGH — requires sector-level market knowledge**

**Setup:** Use data from Q3 2022 when Indian IT sector saw significant correction after
US rate hike expectations increased. Show the system's output for 10 Nifty IT stocks.

**Test procedure:**
1. View signal model outputs for TCS, Infosys, Wipro, HCL, Tech Mahindra on 2022-10-01
2. View sector rotation indicator
3. View HMM regime for sector-level stocks vs Nifty 50
4. Check if portfolio recommendation reduces IT sector exposure

**Pass criteria:**
- [ ] Sector rotation indicator shows money flowing OUT of IT
- [ ] IT stocks show predominantly Hold or Sell signals
- [ ] Portfolio section shows IT sector exposure approaching or at 40% cap enforcement
- [ ] System doesn't give strong Buy signals for IT stocks on this date
- [ ] System correctly identifies that Nifty 50 itself is not in bear regime (IT was sector-specific)

**Failure modes to check:**
- System treats IT correction as a market-wide bear signal and reduces all stocks
- System ignores sector-level signals and gives Buy for defensive IT names
- Macro features (USD/INR) not visibly influencing IT sector signals

## HITL-06: The New IPO Edge Case Test
**Business Value: MEDIUM — new listings have insufficient history for ML models**
**Complexity: MEDIUM**

**Setup:** Take a stock that had its IPO within the last 6 months. Attempt to generate
a signal for it.

**Test procedure:**
1. Run full daily pipeline including the new IPO stock
2. View what happens to the signal output
3. Check if system communicates the data limitation

**Pass criteria:**
- [ ] System correctly marks the stock as having insufficient history (< 252 days)
- [ ] Signal model either: (a) returns NULL/N/A for the signal, or (b) shows significantly
  wider conformal intervals to reflect uncertainty
- [ ] Dashboard shows "Insufficient history" or "High uncertainty: < 12 months data"
- [ ] P&D detector STILL runs for the new IPO (it doesn't need 252 days)
- [ ] Governance features (promoter holding) are still shown even without price history

**Failure modes to check:**
- System silently generates misleading signals with insufficient data
- System crashes or throws unhandled error for < 252 day stocks
- P&D detector disabled for new IPOs (dangerous — new IPOs are often manipulated)

## HITL-07: The Conflicting Signals Test
**Business Value: HIGH — tests the meta-labeler's filtering ability**
**Complexity: HIGH — requires judgment about when to trust multiple conflicting outputs**

**Setup:** Find a stock where:
- Signal 5d says Buy (short-term momentum positive)
- Signal 63d says Sell (deteriorating fundamentals over quarter)
- Meta-labeler says Don't Act
- P&D score is 35 (flagged but not blocked)
- Forensic score is 55 (Amber)

**Test procedure:**
1. Present all model outputs simultaneously on the stock detail screen
2. Human investor must decide: Buy / Hold / Sell
3. After deciding, human looks at what ACTUALLY happened in next 30 days

**Pass criteria:**
- [ ] Dashboard presents ALL signals simultaneously (not just the most recent)
- [ ] Conflicting signals are visually highlighted — not hidden
- [ ] Meta-labeler Don't-Act recommendation is prominently displayed
- [ ] Human investor intuitively understands they should NOT buy this stock
- [ ] The system's aggregate recommendation (if any) aligns with the pessimistic signals
- [ ] Documentation clearly states: "When signals conflict, always defer to the most cautionary"

**Failure modes to check:**
- Dashboard shows only the 5d Buy signal and buries the 63d Sell
- Meta-labeler output is not visible without clicking into a detail view
- System generates a synthetic "overall" signal that averages conflicting signals

## HITL-08: The Model Drift Test
**Business Value: HIGH — ensures you know when the models stop working**
**Complexity: LOW-MEDIUM**

**Setup:** Simulate a situation where the feature distribution has shifted significantly
(PSI > 0.25 on 5+ features). Use data from a genuine market regime shift period.

**Test procedure:**
1. Check the model health dashboard
2. View the PSI report for top features
3. Check whether retrain notification was triggered
4. Human evaluates: Is the explanation of what changed legible?

**Pass criteria:**
- [ ] Health dashboard shows RED status (not just a number in a log file)
- [ ] PSI values shown per feature with plain English explanation
  ("Volume ratio has shifted: stocks now trading at 2.3x average vs historical 1.1x")
- [ ] Retrain alert is actionable (tells human what to do, not just what happened)
- [ ] System correctly REDUCED position sizes during the drift period
- [ ] Human can explain which feature group is driving the drift from the dashboard alone
