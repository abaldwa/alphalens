How AlphaLens Decides What To Buy

One reference for every scoring system in the product — what it computes, how it's derived, and whether it actually drives a decision or just rides along in the data.

This documentation consolidates every scoring system in AlphaLens — technical, fundamental, valuation, and ML — under one menu. Fully written today: Technical (indicators, screener templates, and strategies), ML Signal Engine, and Damodaran Valuation. The remaining systems are stubbed with a scope preview and will be filled in next.

How to read the "Used" status. Every raw indicator in AlphaLens is computed daily for the full universe, but not everything that's computed is actually consumed. Where you see a status pill, it means the codebase was searched to confirm whether a feature is named in an actual screener rule, exit condition, ranking formula, or served by the API/UI — versus only being passed into an ML model in bulk, where it may or may not end up mattering.

Technical Indicators Computed Per Stock, Per Day

What each of the 88 daily technical features measures, its parameters, and whether it's actually used downstream.

70

Every trading day, AlphaLens computes this full set of indicators for every stock in the universe and writes them to a daily feature snapshot. The core layer (features/technical.py) covers the classical technical-analysis toolkit — moving averages, oscillators, trend and volatility measures, Ichimoku, volume/delivery signals. The advanced layer (features/advanced_technical.py) adds signal-processing and chaos-theory diagnostics — wavelet decomposition, entropy, Hurst exponent — that try to characterize how "trending" vs. "noisy" a stock's price series currently is.

The screener layer and strategies don't compute new numbers — they threshold and combine the ones below into buy/sell/watch signals.

Screener Templates

42 named rule templates that turn the raw indicators into buy setups — each one a small AND-combination of feature thresholds, paired with its own exit parameters.

Every template is a ScreenerTemplate — a name, a category, and a list of conditions (lt / gt / lte / gte / eq / between / top_pct / bottom_pct) evaluated against that day's precomputed feature columns, never raw price. A stock qualifies for a setup only when all of its conditions hold on the same day. Templates don't compute new numbers — see Technical Indicators for what each underlying feature means.

Run the Screener /technical-screener ↗ Template alerts /technical-alerts ↗ Technical Overview /technical-overview ↗

Two independent classification schemes coexist. The letter-prefix category (A–F, S) groups templates by the trading philosophy they were modeled after. A separate TEMPLATE_STYLE mapping (Momentum / Trend Following / Mean Reversion / Volatility) reclassifies all 42 templates by actual behavior, and it's this second mapping that drives exit parameters — so a letter-category-A template can carry a "Trend Following" exit profile if its rule is gated by a hard trend filter.

Entry-Filter Tiers

Each of the 42 templates is backtested under three entry-filter intensities — a conservative/balanced/aggressive reading of the same rule set.

TierProfileWhat it does
BalancedDefault riskThe template's standard rule thresholds with no additional entry gating.
Risk-ManagedTighter entryApplies stricter entry filters (higher confidence requirements) to admit fewer, higher-conviction setups.
Max-DefensiveMost conservativeThe most selective tier — strongest trend/quality gates, fewest entries, lowest drawdown profile.

Combo Strategies

Beyond running each template on its own, AlphaLens builds curated Combo strategies via the TechnicalComboAdapter — combinations that pull templates from different behavioral styles (Momentum + Trend Following + Mean Reversion) into one diversified strategy, so the portfolio isn't over-exposed to a single regime's behavior.

The per-variant view also exposes a Signal Failures breakdown — for each losing trade, the entry-signal snapshot that triggered it — so a strategy's losses can be audited back to the exact setup that fired. The single-template view routes each position through its template's own exit parameters (see the exit style table on the Screener Templates page).

Directional Signal

Signal 5D / 21D / 63D

M-02 / M-03

BaseSignalModel stacks 3 base classifiers (LightGBM, CatBoost, XGBoost), each producing out-of-fold 3-class probabilities (Sell / Hold / Buy via triple-barrier labeling), fed into a LogisticRegression meta-learner for calibrated final probabilities. A parallel set of 3 LightGBM quantile regressors (α = 0.10 / 0.50 / 0.90) predicts the forward return distribution. Per-class thresholds are tuned on the validation fold by maximizing one-vs-rest F1 — never a flat 0.5 cutoff. Inputs are the 70+ technical features (63D also pulls fundamentals/governance/MF-holdings/F&O once Phase 2 data is live).

Source: systems/ml_signal_engine/models/signal/

M-04

Exit Policies — 8 variants

All 8 implement the same contract: predict_full(X) returning exit_urgency, exit_type, and exit_survival at 5/21/63d.

1. Exit Signal (ML)

M-07

LightGBM regression for urgency (0–100) + LightGBM classifier for exit type (6 categories) + Cox Proportional Hazards for survival probability at 5/21/63d.

Currently blocked — needs at least 200 real closed paper-trading positions to train; none exist yet.

2. Rule-Based (bootstrap)

Mechanical stand-in for #1 while it's blocked. Flat/ATR-scaled target:stop in a 2:1 ratio, plus max-hold and a P&D-score override.

3. Per-Template

Routes each position by its originating screener template to a rule-based policy configured with that template's own style-derived stop/target/max-hold.

4. ATR-Adaptive

Scales stop (1.5×ATR%) and target (3.0×ATR%) off the position's own entry volatility, falling back to flat defaults when ATR is unavailable.

5. Trailing Stop

Stop triggers on drawdown from the position's peak price, not its entry price; target logic is unchanged from rule-based.

6. Condition-Based

Derives exit triggers from the entry template's own conditions "unwinding" (e.g. an sma_200_ratio > 1.0 entry exits when it drops below 1.0) — independent of P&L.

7. Regime-Conditional

Scales stop_pct by market regime — Bear ×0.7 (tighter), Bull ×1.3 (looser), Sideways ×1.0. Target and max-hold are unaffected.

8. Composite

OR-combines any N wrapped policies via a row-wise MAX of exit_urgency across them.

Source: systems/ml_signal_engine/models/exit/

Multibagger

Multibagger Ranking Model

M-08

LightGBM with a lambdarank objective ranks stocks by probability of a 2×+ return within 3 years. A Platt-scaling LogisticRegression calibrates that ranking score into a 0–1 probability, and a Random Survival Forest fits time-to-multibag to produce survival curves at 6/12/18/24/36 months. mb_tier and mb_archetype are deterministic rule-based post-hoc labels, not separately trained. Inputs: 109 features (76 technical + 33 multibagger-specific); P&D episodes are excluded from positive labels via the P&D detector's score.

Source: systems/ml_signal_engine/models/multibagger/

DCF — 4 Model Variants

All four return a common DCFResult: per-share intrinsic value, enterprise value, equity value, terminal value, terminal value as % of EV, implied terminal EV/NOPAT, and the WACC used.

1–2. FCFF Two-Stage

Phase 1: explicit FCFF grown at a high-growth rate for 5 years (default), discounted at WACC. Phase 2: Gordon Growth terminal value, TV = FCFF_(N+1) / (WACC − g). Raises an error if WACC ≤ terminal growth rate.

3. FCFF Three-Stage

Revenue-driven. Stage 1 high growth at base margin; Stage 2 linear transition (5 years) where growth decelerates to terminal and margin ramps to a stable 12%; Stage 3 perpetuity. Capex/D&A/NWC held at base-year ratios to revenue throughout.

4. Excess Return (banks/NBFCs)

Equity value = BV + PV(excess returns) + PV(terminal excess return), where excess return per period = (ROE − CoE) × BV, and book value compounds at ROE × reinvestment_rate. 10-year default horizon.

7. Commodity-Normalized

For metals/commodities: uses a through-cycle (typically 10-year average) EBIT margin instead of current margin, to avoid extrapolating cyclical peaks. Lower default growth assumptions (4% high-growth, 3% terminal) reflect long-run commodity-sector growth.

FCFFInputs includes a minority-interest deduction in the equity bridge — added after a review found the earlier version omitted it, which overstated per-share value for companies with material listed subsidiaries. Source: systems/damodaran_valuation/dcf/

WACC — India-Specific

Follows Damodaran's 2025 India methodology, not a generic CAPM.

# step by step risk_free_rate = india_10y_yield − india_default_spread (default spread 2.16%) lambda = domestic_revenue_pct / 0.80 (0.80 = "average" domestic exposure) equity_risk_premium = mature_market_erp(4.2%) + lambda × india_country_risk_premium(2.3%) beta_levered = beta_unlevered × (1 + (1 − tax_rate) × D/E) (Hamada) beta_adjusted = 0.67 × beta_levered + 0.33 (Blume, toward 1.0) cost_of_equity = risk_free_rate + beta_adjusted × equity_risk_premium after_tax_cost_of_debt = cost_of_debt × (1 − tax_rate) WACC = equity_weight × cost_of_equity + debt_weight × after_tax_cost_of_debt

Cost of debt comes from synthetic_rating_spread(interest_coverage) — an interest-coverage to credit-rating to Damodaran default-spread table. Unlevered betas are keyed to NSE's real 21-sector taxonomy (e.g. Financial Services 0.45, Information Technology 0.85, Metals & Mining 1.10, Automobile & Auto Components 0.90, Realty 0.95, Default 0.90) — a fix from an earlier version that used made-up sector labels which never matched real data, silently defaulting every stock to 0.90.

Source: systems/damodaran_valuation/dcf/wacc.py

Relative Valuation

PE Regression

Model 5

Cross-sectional OLS: PE = α + β1·EPS_growth_3y + β2·payout_ratio + β3·beta, fit on sector peers (minimum 20 required — fewer leaves near-zero degrees of freedom for a 3-factor fit). Output: actual PE, predicted PE, gap_pct = (actual − predicted) / predicted (positive = trading at a premium to peers), R², peer count, and an overvalued flag when gap exceeds 10%.

Source: systems/damodaran_valuation/relative/pe_regression.py

Scenario Analysis

Monte Carlo DCF

SPEC-VAL-005

Wraps the FCFF Two-Stage model, drawing per-simulation parameters from triangular distributions for growth rate (0.5×–1.5× base) and terminal margin (0.6×–1.3× base), and a normal distribution for WACC (±1% std). Default 10,000 simulations (100 in fast test mode); draws where WACC falls below terminal growth are discarded and resampled.

Output: median value, P10/P90 (bear/bull intrinsic value), probability the stock is undervalued, 5% value-at-risk, and the skew of the value distribution.

Source: systems/damodaran_valuation/scenarios/monte_carlo.py
