Overview

What it is

System 2 in the platform architecture — systems/technical_analysis/ — reads the same daily feature Parquet everything else reads (no private feature copies), and turns it into three consumer-facing tools: a custom screener, a daily alert stream, and per-stock chart/compare views.

  1. screener/engine.py — evaluates every template's conditions against today's (or a chosen date's) feature matrix and returns matching tickers with their key display values.
  2. screener/templates.py — the 42-template library, hand-coded strategy definitions (see below).
  3. screener/outcomes.py — tracks what happened after a template fired, and feeds backtest/strategy_confidence.py's Wilson-interval win-rate scoring per template × regime.
  4. alerts/daily_alert_checker.py + alert_store.py — runs threshold/crossover checks once per day and persists firings for the Alerts screen.

Every hit is scored, not just fired. outcomes.py tracks forward returns after a template match and feeds a Wilson-interval win-rate estimate per (template, market regime) — the same confidence-tiering machinery the Backtest module's strategy_confidence.py uses, so "this template fires" and "this template has historically worked in this regime" are two different, both-tracked facts.

Want the strategy behind each of the 42 templates spelled out — what it's trading, its entry conditions, and whether it's a quick 5-day trade or a multi-month position — plus which style maps to which default backtest horizon? See the full Technical strategy reference. It also covers how a template's strategy_id is codified and how to run/queue a backtest against it.

Daily

Alerts

DailyAlertChecker runs once per pipeline cycle, evaluates the day's feature matrix against the same condition language the screener uses, and persists any firings to alert_store.py — surfaced on the Alerts screen without the user needing to re-run a screener manually.
